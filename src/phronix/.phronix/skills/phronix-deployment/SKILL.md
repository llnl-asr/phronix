## Instructions

### I1 — Deploy into the project

```
phronix deploy            # idempotent: writes only what differs
phronix deploy --check    # writes nothing; exits non-zero if out of date
```

Re-running is a no-op that says so. Use `--check` as a CI gate to catch a
workspace that has drifted from the installed package.

### I2 — Start the stack

```
phronix_stack start       # deploy, then mlflow + collector + mcp server
eval "$(phronix_stack env)" && claude
```

`start` doubles as `refresh`: it compares each running daemon against the
configuration and bounces only what actually changed.

### I3 — Know what deploy produces

| Path | What it is |
|---|---|
| `.phronix/` | the project's knowledge layer — **commit this** |
| `.claude/agents/`, `.opencode/agents/`, `.github/agents/`, `.codex/agents/` | rendered agents (gitignored build artifacts) |
| `.claude/skills/`, `.opencode/skills/` | symlinks into the merged skill store |
| `.claude/settings.json`, `.opencode/opencode.jsonc` | rendered permission blocks |
| `.claude/hooks/`, `.codex/hooks.json`, `.opencode/plugin/` | prompt-injection wiring |
| `.mcp.json`, `.vscode/mcp.json`, `.codex/config.toml` | MCP server registration |
| `CLAUDE.md`, `AGENTS.md`, `.github/copilot-instructions.md` | a managed block inside your own file |

### I4 — Diagnose a stale workspace

`phronix deploy --check` names exactly what drifted. Then `phronix deploy` to
repair. If a file is reported as a conflict rather than updated, it exists and
was not generated by phronix — deploy will never overwrite it.

## Rules

### R1 — Deploy is additive and never destroys your content

Instruction files get a delimited block inserted or refreshed; the rest of the
file is untouched. A file that collides with a generated name but was not
generated by phronix is reported as a conflict and left exactly as it is.

### R2 — Commit `.phronix/`; do not commit the rendered artifacts

`.phronix/` is the knowledge the next clone inherits. The per-harness agent files
and skill symlinks are regenerated from it, and committing them produces a diff
on every model-map change for files nobody edits.

### R3 — A healthy collector is never bounced by `start`

Its profile is in memory. `start` leaves it alone even when its configuration has
drifted; use `restart` when you genuinely mean to lose the accounting.

### R4 — Daemons self-limit their lifetime

Every one is started under a `PHRONIX_STACK_MAX_AGE` deadline (default 8h) so a
forgotten `stop` cannot leave a process running for days on a shared machine. Set
it to 0 for a session that must outlive that.
