# Lessons — phronix-self-learning

Pitfalls and dated lessons for the **recording what a session learned so the next one inherits it** subject. Retrieved by *memory*
search (`context_memory`), not by skill search: "how do I do this" and "what went
wrong last time" are different questions, and keeping them in one file makes every
retrieval of either drag in the other.

## Pitfalls

### P1 — Recording the fix without the symptom

An entry that says only "add `-fcommon` to CFLAGS" is unreachable: nobody
searching for the linker error they are staring at will find it. Always lead with
the error text as it actually appears.

### P2 — Filing a site-specific quirk in a generic subject

A quirk that is true only on one machine, recorded in a generic skill, misleads
everyone else — and is trusted, because it is in the authoritative place. Scope it
to the specific subject and link from the generic one.

### P3 — Widening a skill instead of creating one

When a lesson does not fit the subject, the tempting move is to widen the subject.
Do not: a skill that covers two things becomes findable for neither. Create the
second subject and link it — see [[phronix-skill-authoring#R1]].
