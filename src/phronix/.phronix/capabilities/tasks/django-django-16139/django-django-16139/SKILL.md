## Instructions

### I1 — Update password help_text to include instance primary key

Edit `django/contrib/auth/forms.py` in the `UserChangeForm.__init__` method. Replace the line:
```python
password.help_text = password.help_text.format("../password/")
```
with:
```python
password.help_text = password.help_text.format(f"../../{self.instance.pk}/password/")
```

### I2 — What problem it solves

When a later run accesses UserAdmin via a model's Admin that has `to_field` set to a non-Primary-Key value (e.g., `to_field="uuid"`), the PasswordResetForm link in the UserChangeForm will 404. The symptom is that the password change link generated by `password.help_text` uses `"../password/"` which resolves relative to the admin change view URL, but when `to_field` is used, the URL path includes the custom field value (UUID) rather than just the PK, making the relative path resolve incorrectly. This causes any PasswordResetForm or password change link in the admin to break with a 404 when the User model's admin is accessed through a custom `to_field`.

### I3 — The key idea

The password field's help_text relative path ("../password/") assumes UserAdmin is always accessed via its primary key, but when `to_field` is set to a non-PK value, the admin change view URL path is different (it includes the custom field value like UUID), causing the password reset link to break with a 404.

### I4 — Instructions to solve it

File: django/contrib/auth/forms.py
Function: UserChangeForm.__init__
Change line 166 from:
  password.help_text = password.help_text.format("../password/")
To:
  password.help_text = password.help_text.format(f"../../{self.instance.pk}/password/")
This generates the correct relative path regardless of whether UserAdmin is accessed via PK or a custom to_field admin access pattern. The instruction uses self.instance.pk which accesses the user's primary key and produces a URL path of the form ../../<pk>/password/ that correctly resolves even when to_field is set to a non-PK value.
