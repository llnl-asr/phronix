Analysis from the clean smoke (job 319420, 100k read pairs; the full sample has 4,280,886 read pairs = 42.8x): Nextflow -process.executor=local uses ONE node, so extra nodes do nothing unless the executor changes to slurm (each task its own job; then moirai-service and the node-local podman setup are needed on every task node: a new capability). Per-process times of the smoke (real time): FASTP 2 s; MINIMAP_A 81 s and MINIMAP_B 91 s (index load dominated); ESVIRITU 39 s; CENTRIFUGER 7.8 min; CENTRIFUGE 64 min (cold 427 GB database load, cpus 64); KAIJU_KAIJU 34.5 min (cold 711 GB); SEQSCREEN 33 min for mate 1 (cold 609 GB database) and 5 min for mate 2 (warm cache), RECENTRIFUGE x3 about 1.6 min each; wall 71 min. Scaling estimate for the full sample: database loads are constant, compute scales with reads: SEQSCREEN compute about 5 min x 42.8 = 3.6 h per mate (24 threads fixed by seqscreen_threads), centrifuge about 75 min, kaiju about 40 min, minimap about 10 min each: the critical path is SEQSCREEN, so one node with both mates concurrent gives about 4 to 5 h; with SEQSCREEN one at a time about 7 h (close to the 8 h limit). Node count cannot go below one SEQSCREEN mate (about 3.6 h) unless the reads are split into N chunk samples (samplesheet rows): then N nodes give about 1 to 1.5 h but change the shape of the run (N samples). Chosen: baseline job 319421 on 1 node pbatch -t 480 with SEQSCREEN maxForks 2 (the enable-podman stub removed the race), runs/moirai-baseline; multi-node (slurm executor, or chunked samplesheet) is an option for later.
