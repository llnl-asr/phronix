# Lessons — phronix-memory

Pitfalls and dated lessons for the **the durable memory store of facts, decisions and guidance** subject. Retrieved by *memory*
search (`context_memory`), not by skill search: "how do I do this" and "what went
wrong last time" are different questions, and keeping them in one file makes every
retrieval of either drag in the other.

## Pitfalls

### P1 — A description too vague to match

By far the most common reason a memory is never surfaced. Rewrite it with the words
someone would actually search for.

### P2 — Recording a project-specific fact in the user layer

It then follows you between projects and is invisible to the team it was about.
Check `phronix_status()` before writing.

### P3 — Writing a memory with no links

Nothing pulls it in indirectly, so it surfaces only on a direct lexical hit — which
means it is found when you already knew to look for it, and not otherwise.
