# Lessons: phronix_complexity

- [L-0fc75de4] Assessing an agent whose difficulty is intrinsic to its function -> A planner or synthesiser scores low on scope-derived signals — it loads few skills and calls well-specified tools — and a purely measured verdict will confidently demote it. Declare `intrinsic: max` so measurement can only raise it. -> follow phronix-complexity P1 (Corner cases) (2026-09-15, dftracer-agents phronix-complexity/LESSONS.md P1)
- [L-647770a6] Raising a level instead of building the capability -> A rising score usually means a subject accumulated procedure that should have become code. Buying a stronger model treats the symptom and leaves the drift compounding. -> follow phronix-complexity P2 (Corner cases) (2026-09-15, dftracer-agents phronix-complexity/LESSONS.md P2)
- [L-e00afea1] Never reassessing -> The measurement is only worth anything if it is re-run. An agent assessed once at authoring time and never again is exactly the fixed level the mechanism exists to replace. -> follow phronix-complexity P3 (Corner cases) (2026-09-15, dftracer-agents phronix-complexity/LESSONS.md P3)
- [L-e92fefa1] measured drivers for an agent: +0.300 reasoning_demand (15 rules + 12 instructions), -0.226 tool_coverage (19/21 tools MCP), +0.200 unverified_fraction (2/2 subjects unverified) -> the recommendation is the sum of explainable signals; one nobody can interrogate gets overridden or ignored -> read the drivers and argue with the number, not the verdict (2026-09-15, dftracer-agents phronix-complexity I2)
