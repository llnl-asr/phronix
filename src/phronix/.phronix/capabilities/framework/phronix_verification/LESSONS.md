# Lessons: phronix_verification

- [L-69de9a61] Environment preconditions written as constraints -> The most common authoring error. A dependency check under `constraints` turns every machine without that dependency red. Move it to `assumptions`, where a failure correctly reads as "could not run here". -> follow phronix-verification P1 (Corner cases) (2026-09-15, dftracer-agents phronix-verification/LESSONS.md P1)
- [L-1d369a6d] A scaffolded corrector left unfinished -> `verify_new` without a `source` produces a spec with no constraints. It is reported as a malformed spec rather than passing — but until you notice, the subject looks covered in `verify_coverage()`. Finish it in the same session. -> follow phronix-verification P2 (Corner cases) (2026-09-15, dftracer-agents phronix-verification/LESSONS.md P2)
- [L-518cafca] Correctors that pass because they check nothing -> A constraint like `lambda ctx: True`, or one asserting something the code cannot help but satisfy, produces permanent green. Ask of every constraint: what change to the world would turn this red? If the answer is "none", delete it. -> follow phronix-verification P3 (Corner cases) (2026-09-15, dftracer-agents phronix-verification/LESSONS.md P3)
