# Lessons: phronix_agent_authoring

- [L-8ba9de0c] A template referencing a skill that does not exist -> The agent is told to load something that is not there, and behaves as if the guidance were simply absent. The built-in corrector catches this. -> follow phronix-agent-authoring P1 (Corner cases) (2026-09-15, dftracer-agents phronix-agent-authoring/LESSONS.md P1)
- [L-c43ab99a] Overriding a bundled agent instead of extending it -> A project template of the same name replaces the bundled one entirely, so you stop receiving its future improvements. Consider a project-specific shared section `include:`d into the bundled agent instead. -> follow phronix-agent-authoring P2 (Corner cases) (2026-09-15, dftracer-agents phronix-agent-authoring/LESSONS.md P2)
- [L-12778417] a standing rule changed by editing every template -> before shared sections existed, changing a standing rule meant editing every template, which in practice meant editing most and quietly leaving the rest behind -> add the rule once in common-sections.yaml, include: it, agents_sync (R4) (2026-09-15, phronix-agent-authoring R4)
- [L-06c0e201] an edit to a rendered agent file is silently reverted -> rendered files are re-generated by the next sync -> change the template and agents_sync; the window between edit and revert produces the most confusing bug reports in the system (R1) (2026-09-15, phronix-agent-authoring R1)
