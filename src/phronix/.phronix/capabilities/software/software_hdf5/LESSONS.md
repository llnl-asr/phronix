- [L-33de1c2d] GitHub HDF5 release tarballs return 404 on Tuolumne / Cray PE -> Cray PE network/firewall blocks GitHub release downloads (not version-specific; tested 1.14.4, 1.14.5) -> download from support.hdfgroup.org/ftp/HDF5/releases/hdf5-<maj>.<min>/hdf5-<ver>/src/ with curl -fkL (undated)
- [L-152f896f] dftracer/brahma C++ fails to compile against HDF5 1.14.3 / Cray HDF5 (`chid_t` in H5Apublic.h:932) -> typo `chid_t` in H5Aread_async's declaration (C frontends like IOR tolerate it) -> sed -i 's/H5Aread_async(chid_t attr_id/H5Aread_async(hid_t attr_id/' <prefix>/include/H5Apublic.h (undated)
- [L-a9382d01] L2 HDF5 optimizations compile and run but have zero effect -> HDF5 1.10.x: H5Pset_page_buffer_size no-op with MPI-IO VFD, H5Fcreate_async synchronous -> use HDF5 >= 1.14 (1.14.5 from source) (undated)
- [L-9db9911e] H5Fcreate/H5Dwrite events absent from traces even when annotated -> dftracer built without DFTRACER_ENABLE_HDF5 -> rebuild dftracer with -DDFTRACER_ENABLE_HDF5=ON -DHDF5_ROOT=<prefix> (undated)
- [L-27146954] Parallel HDF5 aggregated writes only 1.05 MB with 2 aggregators on Lustre (Flash-X, 384 ranks) -> each aggregated write is bounded by the Lustre stripe size (8 x 1 MB) -> stripe the fresh output dir 16 x 4M before the first checkpoint, striping_unit = stripe size, more aggregators: 3.76 MB writes, 16 aggregators, write 5.53 s -> 1.45 s (2026-07-08)
- [L-485f7a5b] app's 'use collective HDF5' switch on, but ~one rank holds nearly all write bytes -> the flag never reaches H5Pset_dxpl_mpio(..., H5FD_MPIO_COLLECTIVE) (Flash-X serial HDF5 IO unit hardcodes independent mode) -> confirm collective mode from the trace (few ranks, large pwrites) and fix the code path (undated)
- [L-929d3c24] Cray HDF5 module used for a session breaks dftracer C++ linkage / degrades L2 opts -> header typos, tentative-def issues, PE-drifting version outside the compatible series -> always build HDF5 from source into the session workspace; toolchain-only modules (undated)
