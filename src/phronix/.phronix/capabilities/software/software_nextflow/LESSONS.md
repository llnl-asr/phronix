- [L-ac4d84be] taxteller needs a pinned Nextflow: 26.10.5 fails to parse nextflow.config ("`manifest` is not defined", "`validation` is not defined": the strict v2 config syntax), NXF_VER=25.04.6 (downloaded on the login node with NXF_OFFLINE=false, then NXF_OFFLINE=true in the job) parses it, and nf-schema@2.3.0 must be installed once for that NXF_HOME. The pipeline needs no changes for that. In a Slurm job, podman 4.9 ignores XDG_RUNTIME_DIR/CONTAINERS_CONF for its events dir ("creating events dirs: mkdir /run/user/<uid>: permission denied"): put a podman wrapper first on PATH that execs /usr/bin/podman --root --runroot --tmpdir <node-local> --events-backend=file --storage-opt overlay.ignore_chown_errors=true (the last one because images such as community.wave.seqera.io fastp contain files owned by uid 57439 and the user has no subuid range: "lchown /home/mambauser: invalid argument"). Nextflow tasks and the seqscreen script then use the wrapper. The package podman profile only bind-mounts /p/lustre2: add -v /p/vast1 and -v /usr/workspace in a -c overlay.

- [L-639c53db] Nextflow plugins can be installed on the login node before the compute job: with JAVA_HOME=/usr/lib/jvm/java-17-openjdk, NXF_HOME=<session>/tools/nxf_home, NXF_OFFLINE=false, run `./nextflow plugin install nf-schema@2.3.0` from <session>/tools (about seconds, lands in $NXF_HOME/plugins/nf-schema-2.3.0). - [L-7042e6d8] Nextflow process whose script calls the LC `enable-podman` helper (taxteller SEQSCREEN) must not run concurrently: the helper resets ~/.local/share/containers and /var/tmp/<user>/podman, so two tasks at once race (errors "rm: cannot remove .../containers/cache: Directory not empty", "error creating temporary file", "invalid internal status ... podman system migrate", exit 1). It passes in a plain run only by luck (plain smoke 319353 passed twice). Fix in the site overlay: process { withName: 'SEQSCREEN' { maxForks = 1 } }; cheap because the centrifuge step takes about as long. When a task of a podman pipeline on mammoth exits 1 with those messages, check for enable-podman in .command.sh before looking elsewhere.



- [L-10769698] SEQSCREEN (enable-podman) failures on mammoth were attacked by three fixes in parallel in one chat; keep them as one ordered recipe. Failure: job 319405 (hooks fine) FAILED at 3:21, SEQSCREEN 9 failures despite maxForks 1 and maxRetries 4, because retries are immediate and hit the same window: the LC enable-podman helper runs rm on ~/.local/share/containers/cache on NFS ("rm: cannot remove .nfsXXXX: Device or resource busy" while conmon/pause/catatonit or containers of an earlier cancelled job on the same node still hold files) and resets /var/tmp/$USER/podman ("libpod/tmp/pause.pid: no such file"). Rootless podman processes outlive scancel, so a rerun on the same node sees the old job's files. Recipe: (1) job script at start stops own stale conmon/pause/catatonit and removes /var/tmp/$USER/podman-run-*; (2) either a no-op enable-podman shim first on PATH (tools/bin/enable-podman; the podman wrapper already gives node-local storage) or a SEQSCREEN beforeScript with HOME=/tmp/$USER-seqscreen-home-$SLURM_JOB_ID; (3) keep maxForks 1 and maxRetries; (4) podman run --pid=host so hooks in containers reach the service ring. Verify with .command.err of the first SEQSCREEN within minutes, not at job end.

- [L-66c77145] A Nextflow process whose script calls the LC `enable-podman` helper (taxteller SEQSCREEN) fails on mammoth; fix it with one ordered recipe in the session files, never by editing the pipeline and never as parallel attempts.

Cause: /usr/bin/enable-podman (-> /opt/containers/bin/enable-podman.sh) runs `pkill -xu $USER "podman pause"`, `rm -rf ~/.local/share/containers` and `~/.config/containers`, and rewrites storage.conf (runroot/graphroot under /var/tmp/$USER) on the shared NFS home. It then unsets XDG_RUNTIME_DIR, so podman falls back to a second runtime dir /var/tmp/<user>/podman-run-<uid> while the job wrapper uses XDG_RUNTIME_DIR=$POD_T/xdg; two runtime dirs break rootless podman. Symptoms: "rm: cannot remove .nfsXXXX: Device or resource busy", "Directory not empty", "error creating temporary file", "invalid internal status ... libpod/tmp/pause.pid: no such file", exit 1. It also wipes the user's podman config for every other container and the login node. Rootless conmon/pause/catatonit outlive scancel, so a rerun on the same node sees the old job's files. A single task on a fresh pdebug node passes (probe enable_probe.sh: enable-podman, unset XDG_RUNTIME_DIR, podman run fastp rc 0), so it breaks only while other containers run; plain smoke 319353 passed by luck. maxForks 1 and maxRetries 4 alone fail (job 319405: 9 SEQSCREEN failures at 3:21; job 319409: 9 failures at 6.7 min even with the node-local HOME beforeScript overlay, which fixed only the .nfs error).

Recipe, in order:
1. Job script at start stops the user's own stale conmon/pause/catatonit, removes /var/tmp/$USER/podman-run-*, and creates /var/tmp/$USER and /tmp/$USER.
2. A no-op shim tools/bin/enable-podman (`exit 0`) first on PATH (the session podman wrapper already gives node-local storage). The earlier beforeScript HOME=/tmp/$USER-seqscreen-home-$SLURM_JOB_ID overlay is not needed and is dropped.
3. The podman wrapper does `export XDG_RUNTIME_DIR="${XDG_RUNTIME_DIR:-$POD_T/xdg}"` so an unset variable never selects a second runtime dir.
4. Keep process { withName: 'SEQSCREEN' { maxForks = 1 } } (cheap: the centrifuge step takes about as long) and maxRetries.
5. podman run --pid=host so hooks in containers reach the service ring.

Verify with the first SEQSCREEN .command.err within minutes, not at job end; when a podman task on mammoth exits 1 with those messages, check for enable-podman in .command.sh first. Result: taxteller moirai smoke 319415 (mammoth24, 1h07, rc 0, 20 task rows exit 0, hook log empty, no spill files; 319409 earlier showed fastp, FASTQ_TO_FASTA, MINIMAP_A/B activity records in moirai_mammoth63.pfw.gz). Package note: the reproduction package needs this stub, or a clean node, because enable-podman wipes the user's podman home config.
