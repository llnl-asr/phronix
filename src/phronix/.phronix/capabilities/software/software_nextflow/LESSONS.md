# Lessons: software_nextflow

- [L-0d966b81] Slurm job script pattern for Nextflow with node-local podman storage: run nextflow in the background (`nextflow ... &; NFPID=$!`), `trap 'kill -TERM $NFPID; wait $NFPID; cleanup; exit 143' TERM`, `wait $NFPID`, then cleanup (podman unshare rm -rf <graph>; rm -rf <tmp>): a plain foreground nextflow defers the bash trap until it ends, so scancel (SIGTERM) left the podman storage in /tmp. Template: runs/smoke/run_nf.sh of the taxteller session (args: samplesheet, tag; NXF_RESUME=1 adds -resume for plain runs only).

- [L-ac4d84be] taxteller needs a pinned Nextflow: 26.10.5 fails to parse nextflow.config ("`manifest` is not defined", "`validation` is not defined": the strict v2 config syntax), NXF_VER=25.04.6 (downloaded on the login node with NXF_OFFLINE=false, then NXF_OFFLINE=true in the job) parses it, and nf-schema@2.3.0 must be installed once for that NXF_HOME. The pipeline needs no changes for that. In a Slurm job, podman 4.9 ignores XDG_RUNTIME_DIR/CONTAINERS_CONF for its events dir ("creating events dirs: mkdir /run/user/<uid>: permission denied"): put a podman wrapper first on PATH that execs /usr/bin/podman --root --runroot --tmpdir <node-local> --events-backend=file --storage-opt overlay.ignore_chown_errors=true (the last one because images such as community.wave.seqera.io fastp contain files owned by uid 57439 and the user has no subuid range: "lchown /home/mambauser: invalid argument"). Nextflow tasks and the seqscreen script then use the wrapper. The package podman profile only bind-mounts /p/lustre2: add -v /p/vast1 and -v /usr/workspace in a -c overlay.

- [L-639c53db] Nextflow plugins can be installed on the login node before the compute job: with JAVA_HOME=/usr/lib/jvm/java-17-openjdk, NXF_HOME=<session>/tools/nxf_home, NXF_OFFLINE=false, run `./nextflow plugin install nf-schema@2.3.0` from <session>/tools (about seconds, lands in $NXF_HOME/plugins/nf-schema-2.3.0). Compute nodes then run with the plugin cache already in the session, so the pipeline needs no network for plugins. Check `ls $NXF_HOME/plugins` after the install.

- [L-5b0c690e] Running `nextflow -preview` (parse check of an annotated or plain copy) on mammoth: the default java is 1.8, so wrap nextflow in a session script (<session>/tools/nf17) that exports JAVA_HOME=/usr/lib/jvm/java-17-openjdk, PATH with its bin first, NXF_HOME=<session>/tools/nxf_home and NXF_OFFLINE=true, then execs <session>/tools/nextflow; call it with NXF_VER=25.04.6 (version printed 25.04.6 build 5954). Give --input an ABSOLUTE samplesheet path (a relative assets/samplesheet.csv or the example_dataset paths inside it fail the nf-schema check "the file or directory ... does not exist", which is not a parse error of the copy; the subsample samplesheet runs/smoke/samplesheet_sub.csv worked) and --outdir under /tmp. -preview run inside the pipeline copy leaves .nextflow.log, .nextflow.log.1 and .nextflow/ there: run it elsewhere or delete them, or a stray-files check fails.

- [L-c9551959] Annotated (moirai) Nextflow run on a Slurm-only system (mammoth) is hand-made: taxteller moirai smoke (job 319355, pbatch, 1 node, 4 h, fresh work dir, no -resume; user answer by auto mode "Yes: moirai smoke on pbatch, 1 node, 4 hours") used runs/moirai-smoke/run_nf_moirai.sh, a variant of the plain nextflow_slurm_script output that adds: (1) moirai-service start before nextflow and stop in the SIGTERM/exit cleanup; (2) DFTRACER_ENABLE and a trace dir in the session; (3) MOIRAI_BASE_RUN_OPTIONS exported with the old podman.runOptions, because moirai_overlay.config REPLACES podman.runOptions (taxteller value: '--runtime crun --group-add keep-groups -v /p/lustre2:/p/lustre2 -v /p/vast1:/p/vast1 -v /usr/workspace:/usr/workspace'); (4) -c order: site overlay first (mammoth_overlay.config, seqkit container), moirai_overlay.config last; (5) job_lines.sh from the annotate stage; plus node-local podman wrapper, registry auth file, MOIRAI_BIND_PATHS of the venv and its python. Integrate on mammoth: integrate_apply with an empty build_command writes provenance/moirai_env.sh ("nothing to build") and integrate_validate passes 2 of 2 (no _moirai_prov.py exists for Nextflow; the helper is moirai/_moirai_nf.py). moirai_smoke_run/moirai_baseline_run only submit through flux, so this is not covered. Capability needed: a moirai option of nextflow_slurm_script (moirai=True: service, overlay order, base run options, MOIRAI_NF_LOG) plus a validator that reads sacct and the moirai traces (moirai_run_attach with a Slurm job id), so integrate/moirai_smoke stop being hand-written. Risk to check after the run: the hook runs INSIDE podman tasks, so the venv python must run in the container (glibc, bind mounts); a silent skip leaves no events and is visible only in the moirai traces and MOIRAI_NF_LOG.


- [L-7042e6d8] Nextflow process whose script calls the LC `enable-podman` helper (taxteller SEQSCREEN) must not run concurrently: the helper resets ~/.local/share/containers and /var/tmp/<user>/podman, so two tasks at once race (errors "rm: cannot remove .../containers/cache: Directory not empty", "error creating temporary file", "invalid internal status ... podman system migrate", exit 1). It passes in a plain run only by luck (plain smoke 319353 passed twice). Fix in the site overlay: process { withName: 'SEQSCREEN' { maxForks = 1 } }; cheap because the centrifuge step takes about as long. When a task of a podman pipeline on mammoth exits 1 with those messages, check for enable-podman in .command.sh before looking elsewhere.

- [L-62d0cd83] Annotated Nextflow run in podman on mammoth: any host path a hook or helper writes or reads inside the task (trace dir, MOIRAI_NF_LOG, helper, venv python) must be in a podman bind; the session under /usr/WS2/... is NOT bound by the base runOptions (only /p/lustre2, /p/vast1, /usr/workspace). Put MOIRAI_TRACE_DIR in MOIRAI_BIND_PATHS in the job script (nextflow_slurm_script moirai option still to be built) and in the overlay binds, or place the trace dir on a bound filesystem. A task that works but exits 1 with ".command.sh: line N: <trace dir>/nf_hook.log: No such file or directory" in .command.err is this case.

Evidence case: taxteller first annotated (moirai) smoke, Slurm job 319355 (pbatch, 1 node, mammoth63) FAILED rc 1 after 12:31 (sacct 1:0, 7.6 MB moirai trace pfw.gz still written). FASTP ran; MINIMAP_A did its work (minimap2 index load ~10 min, 195,532 sequences mapped, outputs and versions.yml present) but exited 1 because the hook's `2>>"$MOIRAI_NF_LOG"` pointed at <session>/runs/moirai-smoke/traces/sub/nf_hook.log, unmounted in the container, and the failed redirect under `bash -e` changed the task exit status.

Diagnosis method that worked: sacct -j, tail of slurm_<id>.out, grep ERROR in logs/nextflow_sub.log, then .command.err and .command.sh of the failed work dir (the last line of .command.err named the redirect). The pipeline had to be re-run fresh; apply the tools_nextflow_annotate fix (proposal 2db065f27c4a), re-apply the annotation to the copy, and ask before another 4 h pbatch job. Afterwards check that every task wrote its events (the hook runs inside podman).
